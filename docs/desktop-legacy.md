# OpenAI 批量重新授权

独立的 Python/Tk 窗口工具：本地生成 Codex PKCE OAuth 授权链接，通过 Playwright 登录 OpenAI、交换 token，导出 sub2 或 CPA JSON。授权、转换与接码可独立运行；「自动推池」可以连接你配置的 sub2api 后台，批量新增或更新账号。

界面采用中性深灰设计 token、DWM 暗色标题栏、绿色主操作按钮与固定左侧导航，按「账号处理」与「数据管理」分类。四个功能在同一窗口切换并保留输入。授权设置按网络、运行、导出分组；接码设置按号码、重试、运行分组，网络模式和显示浏览器固定展示。推池设置按连接、分组、模型分组，处理结果与运行日志使用页内标签切换。设置使用等宽分段控件，可独立滚动。输入区与空结果表按内容显示细滚动条；占位提示不进入实际文本，转换预览在脱敏后进行 JSON 高亮。手机接码 Key 可临时显示／隐藏；授权页统计、日志与运行状态统一着色。默认窗口为 1280×860（小屏自动适配）。

步骤等待的倍数仅接受 0.1–10 的有限数值；停止或总时限到达后不再继续填写、提交。已经发出的请求无法撤回，已确认的绑定结果和订单收尾仍需保存。验证器验证码在提交前的等待结束后生成，避免等待期间跨过验证码有效周期。

## 安装与启动

需要 Python 3.10+。在本目录用 PowerShell 执行：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m playwright install chromium
.\start.bat
```

已安装的 Microsoft Edge/Chrome 也可被使用；若系统浏览器可用，安装 Playwright Chromium 是可选的。启动器本身不会自动下载或安装依赖。

日常双击 `启动重新授权.bat` 或桌面快捷方式。启动器优先使用本目录 `.venv`，其次通过 `py -3` 或 PATH 查找 Python；启动错误写入本目录 `gui-error.log`。移动工具目录后，在新目录运行以下命令重建桌面入口：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\make_shortcut.ps1
```

## 批量授权

每行输入一个账号：

```text
email@example.com----password----TOTPSECRET
```

密码包含 `----` 时，第一段作为邮箱，最后一段作为 2FA 密钥，中间内容整体作为密码。

粘贴账号、选择导出格式后点击「开始授权」。默认静默运行，进度显示在日志中；需要查看登录页时勾选「显示浏览器」。账号停用、错误密码、手机验证等会停止该账号的自动尝试；遇到限流会暂停整个批次，剩余账号不再尝试。需人工交互、失败或未处理的账号可通过「重试未成功账号」继续，重试自动显示浏览器；也可以只输入一个账号单独重试。

授权页也支持带 OAuth 凭据的 sub2、CPA 和其他已支持的 JSON。存在 `refresh_token` 时先向 OAuth token 接口刷新，成功后直接作为可导出结果，不启动浏览器；账号行仍按原流程登录。刷新被拒绝、网络中断、响应无效或账号／工作空间身份不能确认时，保留为「刷新失败／待核对」。点击「重试失败」后，工具会询问是否改用浏览器重新登录；选择否不会重登，重新点击开始也不会重复提交已有不明确记录的旧令牌。没有密码／2FA 的 JSON 可以在确认重登后通过可见浏览器手动完成登录。命令行遇到此类结果返回失败状态，不自动打开浏览器。

刷新前后记录保存在 `recovery/token-refresh/*.dpapi.json`，使用 Windows 当前用户 DPAPI 加密。服务返回轮换令牌后先保存，再校验身份与有效期；加密或存储失败会停止。再次导入相同旧令牌时优先恢复已确认成功的结果，结果过期时只使用已确认的最新刷新令牌；结果不明确时不自动重放。相同恢复目录中的多个工具实例不能同时刷新同一个令牌。此机制不协调其他软件对同一账号令牌的使用；请保留原输入及恢复记录。纯转换页和手机接码页不调用此刷新流程。

授权设置新增「使用代理」。支持 `IP:端口:用户名:密码`、`主机:端口` 和完整代理 URL；代理协议可选 HTTP、HTTPS、SOCKS5（默认 HTTP）。无协议地址按所选协议使用，`http://`、`https://`、`socks5://` 完整 URL 则以自身协议为准，支持带用户名和密码的 SOCKS5。输入非空地址会自动启用，也可取消勾选而保留输入。代理同时用于浏览器登录和 token 交换，本机 OAuth 回调不经过代理；配置无效时会在启动前提示。输入框隐藏凭据，日志仅显示是否启用代理。「在本机加密记住代理」默认启用，开始授权或关窗时保存到 `auth_settings.json`，通过 Windows 当前用户 DPAPI 加密；取消记住会移除已保存的代理凭据，本次仍可继续使用。换电脑、换 Windows 用户或加密不可用时需要重新填写。右侧设置栏可滚动。

账号有多个工作空间时，自动优先选择组织／团队等非个人空间，再点击继续。已选中的组织可用时保留该选择，否则按页面顺序选择第一个可用组织；只有个人空间时才选择个人空间。如果组织存在但均不可用，会提示需要人工选择，不自动退回个人空间。支持中文和英文选择页。

浏览器授权每成功一个账号，立即更新 `recovery/<本轮目录>/accounts.json`；已有令牌刷新的恢复位置见上文。手动导出前程序中断时，可从对应恢复记录找回结果；`accounts.json` 包含敏感 token，应妥善保管。取消或正常关窗会请求停止任务并清理浏览器、回调监听等资源。默认不保存页面截图或 HTML。

## JSON 导出与格式转换

格式逻辑集中在 `reauth_formats.py`。点击左侧「格式转换」，在同一窗口切换页面；点击左侧「批量授权」即可切回。切换时保留各页输入与结果，后台任务继续运行。

支持粘贴 JSON、选择一个或多个文件、选择目录，识别：

- 完整 sub2 wrapper（包含 `exported_at` 和 `accounts`）。
- 单条 sub2 账号对象（包含 `credentials`，无 `accounts` 包装）。
- CPA 账号对象。
- ChatGPT 网页 Session（`accessToken`、`user.email`、`account.id` 等）。
- 9router Codex OAuth（`provider=codex`、`authType=oauth`、`accessToken/refreshToken`、`providerSpecificData` 等）。

支持 UTF-8 BOM、数组、混合格式和连续的 JSON 对象。统一的「导入 JSON 文件／目录」按文件处理，坏文件会列出文件名和原因，其余文件继续导入；粘贴内容有错误时不会静默丢掉其中的账号。目录读取当前层级的 JSON 文件，不递归扫描子目录。识别后可选择预览格式，再保存为完整 sub2 JSON，或按邮箱拆分 CPA 文件。同邮箱的多个空间分别保留，输出重名时添加序号，不覆盖已有文件。

转换页显示邮箱、空间 ID、声明有效期和刷新令牌是否存在。检查完全离线，不会调用登录、刷新或短信接口；「有刷新令牌」不表示令牌已验证有效。过期、缺少刷新令牌、缺少空间 ID、身份字段或到期时间冲突会在预览和保存时提示。token 声明仅用于读取元信息，未进行验签；显式字段优先，缺失时才尝试补齐，冲突不会静默覆盖。

网页 `sessionToken` 不能替代 OAuth `refresh_token`；网页的 `expires` 仅作为会话有效期保留，不冒充 access token 的到期时间。转换不会延长有效期或获得新权限，也不生成占位 `id_token`。导入外部工具生成的无签名／合成 ID token 时保留原文并提示，不用它补齐身份和套餐信息。

Session／9router 输入适配位于 `reauth_conversion.py`，由转换页与自动推池页复用；原授权与接码输入仍使用原解析入口。输入中真实的 access/refresh/id token 保留；来源未给出 `client_id` 时不擅自指定客户端。未映射的来源字段保存在 sub2 的 `extra.openai_reauth_conversion`，导出标准 CPA 时提示这些字段会丢失。

- **sub2**：导出 `accounts[]` 和账号凭据，`expires_at` 使用 Unix 秒。
- **CPA**：使用标准 9 字段 `type/email/expired/id_token/account_id/disabled/access_token/last_refresh/refresh_token`；时间使用 `+08:00`。

转换不是无损备份。标准 CPA 无法携带 sub2 的 `model_mapping`、`extra`、并发与优先级等额外配置；转成 CPA 再转回 sub2 无法恢复这些字段。工具会提示有损转换，但不会生成保留额外字段的 sidecar 文件。原始数据需要保留时，请自行保留原文件。

缺少 `last_refresh` 时，若 access token 的 JWT `iat` 可用，会将其作为近似时间并提示；该值并不证明真实刷新时间。

sub2 导入器不支持通过这些导入数据恢复 `disabled` 状态；即使文件保留了相关元数据，导入也不会自动停用账号。需要停用的账号必须在导入后手动停用。

## 自动推池（sub2api 后台）

点击左侧「推送到池」在同一窗口切换页面。使用步骤：

1. 填写站点地址，例如 `https://sub2.example.com`。支持端口、部署前缀，也可填写以 `/api/v1` 或 `/api/v1/admin` 结尾的地址；不要填写后台网页的 `/admin/accounts` 地址。
2. 选择「管理员 API Key」或「管理员访问令牌」，填入对应凭据。前者使用 `x-api-key`，后者使用 `Authorization: Bearer`；普通用户的调用 Key 不能代替管理员凭据。
3. 点击「连接并加载分组」，读取当前站点启用的 OpenAI 分组；点击列表可选择多个分组。该按钮只读取信息，不创建账号。修改站点或认证信息后必须重新加载分组。
4. 配置优先级、每个后台账号的并发数、后台账号代理和负载系数。优先级数值越小越优先；并发数是写入后台账号的调度配置，批量推送本身按顺序执行。也可选择保留原优先级和并发数。
5. 粘贴账号或导入文件／目录，点击「识别账号」检查列表，再点击「开始推送」。结果表显示新增、更新、待补手机、失败原因及后台账号 ID。

右侧「账号模型限制」支持三种模式，并随推池配置保存：

- **沿用输入账号配置**（默认）：输入 JSON 有 `model_mapping` 时采用输入值；未提供时，更新账号保留后台原值，新账号不添加该限制。
- **设置模型白名单**：同步上游模型后勾选需要保留的名称，也可添加自定义模型。推送时为新建和重复账号统一替换原白名单及模型映射。必须至少保留一个模型，全部移除不会自动解除限制。
- **清除模型限制**：明确清除原白名单和模型映射，按后台默认规则调度；不表示账号能够调用上游不支持的模型。

模型选择方式与当前 sub2api 后台保持一致：连接后台后，选择「设置模型白名单」→「加载来源账号」，在下拉框选择一个后台已有的 OpenAI OAuth 账号，点击「同步上游模型」。工具调用当前项目的 `POST /api/v1/admin/accounts/{id}/models/sync-upstream`，由后台通过该账号的凭据和后台网络／代理读取模型。同步可能更新该来源账号的模型能力缓存，不创建账号、不提交本次白名单；只有点击「开始推送」才应用白名单。当前项目的未保存账号预览接口不接受 OAuth access token，因此后台尚无 OAuth 账号时，先以默认模式推送一个账号作为来源，或手动添加模型。

列表支持搜索、点击方框保留／移除、选择行后按空格切换或 Delete 移除，以及「全部保留」「全部移除」。移除表示不纳入待推送白名单，仍可重新勾选。同步合并新返回的模型，保留已有勾选和移除状态；新出现的模型默认勾选。同步失败、取消或返回空列表时，保留原列表；不会自动换成静态示例，也不会自动重试上游请求。移除状态随配置保存，旧版手填模型会迁移成已勾选条目。

自定义模型支持多行及英文／中文逗号、分号分隔，点击「添加自定义模型」后进入选择列表并自动去重。只接受完整名称，不接受通配符、JSON 或映射表达式。来源列「同步」表示本次后台同步接口返回的模型；「未返回」表示手动添加、先前保留或尚未重新同步的条目，工具不会静默删除它们。同步采用后台当前的逻辑；后台在上游列表接口不支持时可能回退已有模型配置，模型能力信息也可能不完整，相关提示会保留。同步结果来自所选来源账号，不保证批次中其他账号或套餐也支持所有模型。

白名单按 sub2api 的 `credentials.model_mapping` 同名映射格式提交，并核对后台写入结果。后台已开启「自动透传」的重复账号不会执行白名单更新，会提示先关闭透传；工具不会自行修改透传开关。

白名单配置改变后，可点击「开始推送」更新之前已成功的账号；存在结果待核对的写入时，需保持前次白名单及其他配置先重试核对。此设置只作用于自动推池，标准 CPA 导出仍保持原来的九字段。

输入可混合使用 `邮箱----密码`、`邮箱----密码----2FA密钥`、完整 sub2、单条 sub2 账号、CPA、ChatGPT 网页 Session 和 9router Codex OAuth；JSON 支持数组及连续对象。多文件可混合选择 JSON/TXT；目录读取当前层级的 JSON/TXT 文件，坏文件会在日志中列出，其余文件继续载入。邮箱收码地址不是登录密码，此类输入继续在接码页使用。

已有 refresh token 的 JSON 先刷新成功再推送；刷新失败或结果不明确时，该账号停留在待选择状态，不上传旧凭据，也不自动重登。点击「重试未成功」并确认后才改用浏览器重新登录；原输入的空间和账号身份必须与登录结果匹配，否则不推送。只有 access token 的 JSON 继续走原有效期检查和推送。账号密码输入复用现有 OAuth 批量登录及工作空间选择流程，成功后立即推送。登录和刷新代理沿用授权页设置，后台管理 API 使用当前默认网络／环境代理。缺少 2FA 密钥或需要邮件验证码时，可开启「显示登录浏览器」人工完成；静默模式将其标为需人工验证。遇到手机验证立即跳过并标记「待补手机」，不调用接码服务、不购买号码，其余账号继续。

「分组」设置中的**后台账号代理**通过「加载后台代理」读取当前站点启用的代理，只保存所选 ID。默认「保留后台代理」不更改已有账号绑定；「直连（清除绑定）」明确解除已有绑定；选择具体代理则在写入前校验该代理仍有效。新账号未选代理时使用后台默认直连。这是后台调用模型时的出口，与工具自身登录／刷新用的代理分别设置；不会把本机代理密码上传为后台代理。

**负载系数**支持 0–10000 的整数：留空保留已有后台值，0 恢复后台默认行为，正整数写入本次配置。在保留调度配置模式下，新账号优先沿用输入的优先级、并发和负载系数；输入缺少值时使用页面默认设置。代理或负载系数改变后，可以再次更新已成功推送的账号。写后会核对后台返回的配置，不一致时标为待核对，不冒报成功。

重复账号按「工作空间 + 用户 ID」识别，缺少用户 ID 时使用同空间内的邮箱辅助匹配；同邮箱不同空间、同团队不同成员会保留为不同账号。后台存在多条相同身份、缺少必要标识或与 token 身份冲突时，不自动猜测覆盖，结果会提示核对。JSON 必须包含可推送的 access/refresh token、空间 ID，以及用户 ID 或邮箱；只有 `sessionToken` 的网页会话不能代替 OAuth 凭据。

重复账号**更新凭据及配置**：分组替换为本次所选分组，优先级、并发数按所选覆盖／保留策略处理，并更新名称和本次提供的 OAuth 凭据。本次缺少 refresh/id token 时保留后台已有值；后台未在本次输入提供的模型映射等凭据配置，以及已有额外信息和启停状态会保留。代理和负载系数仅在明确选择覆盖／清除时改变。输入里的密码、2FA、邮箱接码地址、网页会话原文和转换来源备份不上传到后台；合成或无签名的 ID token 不作为真实凭据上传。新账号只写入规范 OAuth 凭据和本页配置，不整体复制来源 JSON 的额外运行设置。

缺少刷新令牌时会提示续期限制：有效 access token 可以推送，但到期后需要重新获取；已过期且没有 refresh token 的输入会拒绝推送。推送成功表示后台确认了账号及分组配置，不等于已经测试 OpenAI 可用性或验证刷新令牌有效。

点击「重试未成功」只处理未成功项；当前页面保留已获取的 OAuth 凭据，推送失败后不用重复登录。保持输入和配置时，重复点击开始不会重做成功项；改变分组、优先级或并发数后点击开始，可以再次更新这些账号的配置。网络结果不明确时标记「结果待核对」并停止批次，保留原请求及幂等标识；请保持原输入、站点和配置后重试，先核对前次写入。关闭页面前未确认的结果应保留报告，重新启动后先检查后台账号再导入。幂等保护依赖目标 sub2api 当前管理 API 的支持，不覆盖其他客户端同时新增相同账号的情况。

管理员凭据默认使用 Windows 当前用户 DPAPI 加密保存到 `pool_push.json`，加密失败不会回退为明文；取消「在本机加密记住凭据」后只在内存使用。日志不记录 token、密码或管理员凭据。脱敏处理报告自动保存在 `recovery/pool-<本轮目录>/report.json`；账号密码 OAuth 成功的凭据仍按原机制写入另一个本轮恢复目录的 `accounts.json`，该文件含敏感 token。

授权、接码和推池任务共享运行锁；页面切换保留输入与结果。点击停止或关窗后等待当前请求和浏览器收尾，不强行中断正在提交的写入。右侧设置栏贯穿结果与日志区域，可用滚动条或滚轮查看底部设置。

### 只读号池巡检

连接后台后，在推池页切换到「只读巡检」，点击「读取号池状态」。选中了分组则只检查这些分组；未选分组时检查全部 OpenAI OAuth 主账号。巡检仅调用账号分页列表与代理列表的 GET 接口，不启动登录、不刷新 token、不补手机、不探测模型，也不修改启停、分组或其他后台配置。

检查后台异常／禁用状态、调度开关、限流及过载冷却、凭据与账号到期、刷新令牌存在性、代理有效性、分组和身份缺失，以及同身份重复／冲突。后台没有提供某字段时显示「未知」，不把缺字段判成无效凭据。列表与可导出的 JSON 报告仅包含必要账号标识和固定问题描述，不包含 token、密码、管理员凭据或后台原始错误正文。停止或查询失败时保留上次完整结果；切换连接会清除旧站点报告。

巡检是**后台已存状态快照**，并非上游实时可用性测试；「未发现异常」不代表已验证账号能够调用模型。发现问题后由用户决定后续处理，不自动修复或重新登录。

## 自动接码（已有账号补手机号）

点击左侧「手机接码」进入同一窗口内的接码页。它处理已有 GPT 账号的补手机挑战，不进行手机号新注册。普通「批量授权」仍跳过手机验证，不会使用短信余额；授权和接码一次只能运行一个批次，页面切换不终止当前任务。

输入支持完整 sub2、单条 sub2 账号、CPA、`邮箱----密码----2FA密钥` 和 `邮箱----密码`。可选择多个 JSON/TXT 文件或一个目录，文件分别解析，因此可以混合导入；不可读或格式错误的文件会显示文件名。JSON 中的登录密码可放在 `extra.password`、`credentials.password` 或顶层 `password`，TOTP 密钥可使用 `extra.totp_secret`。原始 token 不是网页登录会话，仅有标准 CPA/sub2 token 的账号不一定能自动登录。

也支持 `邮箱----邮箱接码地址`：第二列为 `http(s)://主机/messages/访问令牌/邮箱`，支持粘贴 Markdown 链接。JSON 可用顶层或 `extra.mailbox_url`。程序在发起登录前记录历史邮件，只读取此后收到的 OpenAI 登录验证码，支持 iCloud 转发邮件和垃圾邮件文件夹；不会把接码地址当作密码、不会打印访问令牌或验证码。另已支持 `msg.linlanyu.com` 的单封邮件 JSON 接口，校验收件人、发件人、验证码及带时区的收件时间，排除历史邮件。邮箱登录只对接码页启用，原授权页不受影响。其他邮箱服务的接口结构需要单独适配。

在右侧填写 SMSBower API Key，从中文名称下拉框选择国家（如「加纳（Ghana）」），无需记忆供应商代码。接码国家和备用国家的候选列表均按中文拼音 A–Z 排序；已添加的备用国家按列表顺序重试，可上移、下移。配置一号最多绑定 X 个账号、最高单价、单账号超时、大小重试次数和网络模式；最高单价留空代表不限制，填写时必须大于 0。已添加备用国家但大重试为 0 时，界面和启动日志会提示本轮不会换国。设置栏可独立滚动；「网络模式」和「显示浏览器」固定在设置区顶部。

接码页的「网络模式」有三个选项：

「网络模式」和「显示浏览器」固定在右侧顶部的「登录方式」区域，不随短信设置滚动；遇到授权页 HTTP 403 时可直接检查这两个选项。当前电脑的对照测试中，系统代理＋可见系统 Chrome 能显示邮箱登录表单，静默 Edge 返回 403；这只验证打开登录页，不代表账号已完成接码。

- **系统代理**：新配置默认选择。开始时读取 Windows 当前用户的静态代理，整批浏览器、邮箱、短信和换票使用同一个地址；系统未启用代理则统一直连。读取失败、自动代理脚本（PAC）／自动检测（WPAD）或 HTTP/HTTPS 使用不同地址时，启动前提示填写一个自定义代理，不会静默换用直连。系统的按站点绕过规则不继承，仅保留本机 OAuth 回调直连。
- **直连**：不使用系统或环境代理，保留已填写的自定义地址。
- **自定义代理**：使用填写的 HTTP、HTTPS 或 SOCKS5 地址；完整 URL 以自身协议为准。地址与协议控件仅在此模式启用。

旧配置启用代理时迁移为自定义代理，关闭时保留为直连并提示差异。「显示浏览器」仍保存原值；新配置默认显示。启动日志和结果 JSON 记录网络来源、实际直连/代理协议、国家、价格上限及显示模式，不保存代理地址或凭据。接码继续复用已有 OAuth 登录流程，使用浏览器原生 User-Agent；静默优先 Edge，可见优先 Chrome。普通授权及 JSON 转换不受这些接码专用设置影响。

如果手动 Chrome 使用 Windows 系统代理，接码页请选择「系统代理」；对照测试还需要核对号码国家、价格和浏览器显示模式。接码可见模式优先查找系统目录中已安装的 Chrome，再尝试 Playwright 的 Chrome 通道、Edge 和内置 Chromium，避免用户目录残留旧 Chrome 导致启动失败。`fraud_guard` 表示 OpenAI 拒绝了手机验证请求，具体原因不能仅凭该错误确定；发送阶段失败会明确注明尚未进入短信轮询，并保留熔断及订单收尾。收到短信与提交验证码完成绑定仍分别判定。

接码页默认启用「自动匹配最低可用价」。选择国家后自动通过只读 `getPricesV3` 查询报价，也可点击「读取当前国家报价」刷新；填写或修改 API Key 后离开输入框也会查询。界面显示匹配价格、报价库存、供应商数量及其他价位，不会因读取报价而购买号码。修改国家、Key 或网络设置后，旧报价失效；晚到的旧查询不会覆盖当前国家结果。修改最高单价会即时重新计算已读取报价。

自动匹配模式每次买号前重新读取当前国家报价，选取限价内最低价的供应商，并将该报价同时作为本次请求的最低价和最高价。返回 `NO_NUMBERS` 时，本批次后续重试跳过该供应商的同价报价，在原重试次数内尝试下一个合格价格档；备用国家按当地报价单独匹配。最高单价不会被报价自动覆盖，留空代表用户选择不限价。比如最高价为 0.08，0.064 的供应商缺号后，不会自动购买 0.126 的号码；需要手动修改限价。

关闭自动匹配时保留原买号方式：缺号后的重试查询报价并指定价格范围内的供应商。报价是参考数据，即使显示有库存也可能无法实际分配；日志会区分报价无合适库存与报价有库存但分配失败。查询失败、停止或超时不会继续本次购买。供应商返回的订单价格若超过自动匹配报价或格式无法确认，会记录订单、请求取消并停止；取消未确认时保留订单待清理。

登录遇到补手机页后，程序买号、发送短信、等待验证码并提交；只有确认 OpenAI 验证成功才计入绑定次数。号码达到 X 次后结束该订单，再购买新号。最高单价是每个号码的采购上限，X 是工具本轮的复用上限，不能保证 OpenAI 接受同一号码绑定 X 个账号。

小重试在当前国家换号码：设置 N 次表示首次失败后最多再试 N 次；默认 2，填 0 则该国只尝试一次。大重试在当前国家的小重试用尽后切换国家，进入新国家后重新执行首次尝试和 N 次小重试；默认 0。备用国家支持中文选择、添加、上移、下移和移除，按列表顺序使用，不随机选择、不重复循环。设置大重试 M 次时，需要至少 M 个与首选国家不同的备用国家；配置不足时启动前提示。

例如小重试 2、大重试 2，并配置两个备用国家，最多处理 3 个国家，每国最多 3 次，共 9 次尝试。已有成功使用且仍有复用额度的号码优先继续使用，包括备用国家号码；其国家移到本账号尝试顺序首位，国家集合与总预算不变。没有可复用号码时从首选国家开始。缺号、OpenAI 明确拒号和短信超时共用尝试预算；买号不会另行叠加重试。切换国家前会释放上一张号码，已有成功使用记录的订单请求完成，否则请求取消；释放无法确认则停止。各国沿用同一最高单价，不自动加价。

全部尝试共用单账号超时，可能在达到重试上限前结束。大小重试或接码总时限耗尽会熔断并停止本批次，剩余账号标为未处理，已成功的结果保留。次数、备用国家及顺序随接码设置保存；旧版自动重试配置作为小重试保留，大重试默认关闭。登录密码或人工交互失败仍按原有逻辑处理，不属于接码重试。

余额不足、Key 无效、限流、买号结果不明确或 OpenAI 的 `fraud_guard` 风控拒绝会立即停止整批，不触发小重试或大重试。该错误不能仅凭响应确定是号码、网络还是账号导致；增加重试次数不能保证绑定成功。重试耗尽或风控拒绝时，界面显示「已熔断」及补绑、失败、未处理数量，运行记录保留停止原因。调整配置后可以手动重新启动。

手机号表单按国家控件选择区号，支持中英文标签、原生下拉及可确认已选状态的自定义下拉；未知或有歧义的控件停止发送。提供通道选项时明确选中短信并确认 WhatsApp 未选中。发送前还会拦截核对实际请求中的完整号码与通道，不匹配则阻止请求；整个收码和验证码提交阶段继续阻止页面重复发送。成功后保留拦截直到该账号的浏览器页面关闭，避免页面定时器再次发送短信或提交验证码。无法核对的请求停止处理，不自动换号掩盖表单错误。

运行记录新增号码尾号、通道、HTTP 状态、已知错误代码和格式受限的请求 ID；相关请求头只记录是否存在，不保存头部内容、验证码或原始请求正文。错误提示优先使用服务端明确的错误代码，泛泛的“稍后再试”不会直接归类为限流。请求头是否存在本身不表示它有效，也不能单独用于判定风控原因。

结果将「实际补绑成功」与「OAuth 完成但未补绑」分开。账号直接完成 OAuth、没有出现手机页，不会被记为本次补绑成功；手机号已绑定而后续换 token 失败时，仍保留绑定成功状态。页面还分别显示失败、取消和未处理数量，具体原因查看运行记录。

缺少密码、TOTP 或需要邮箱验证码时，自动流程不能凭 token 绕过登录。需要人工操作的账号可勾选「显示浏览器」重试，在浏览器中完成当前登录步骤；静默模式无法替代人工收取邮箱验证码。

「在本机加密保存 Key / 代理」默认启用，使用 Windows 当前用户的 DPAPI 加密后写入 `phone_smsbower.json`，旧明文配置会在读取时迁移。取消该选项后，本次仍可使用内存中的 Key，配置文件不保存 Key 或代理凭据。将加密配置复制到其他机器或用户账户时需要重新填写。加密不可用时不回退为明文保存，日志和错误提示会隐藏本次 Key 等凭据。

点击停止或关闭窗口后，程序先请求停止，再处理活动短信订单并释放浏览器；在网络请求结束和订单收尾前窗口可能保持打开。未用过的号码请求取消，已成功使用的号码请求完成。供应商未确认完成或取消时，订单 ID 和待处理动作保留在 `recovery/phone-orders.json`，下次接码优先重试这些动作；不要删除记录来跳过未解决的订单。供应商的取消条件和计费规则决定是否退费，程序不能保证取消即退款。成功换取的 OAuth 凭据仍写入 `recovery/<本轮目录>/accounts.json`，请妥善保管。

接码批次在读取订单恢复记录前获取 `recovery/phone-orders.lock` 的跨进程锁，持有到订单清理结束；第二个实例会提示已有任务，不能清理另一个实例的订单。进程退出后操作系统释放锁，不需要手动删除锁文件。更新程序后请关闭并重新打开旧窗口，使所有实例使用此保护。
