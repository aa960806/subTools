# 自动注册分支合并审查

审查对象：`origin/codex/automatic-registration`，提交 `65a267b`；基线为主分支 `eecc445`。维护目录为独立的 `F:\SubTools`。

新增独立注册页、邮箱输入、Microsoft Graph 邮件读取、注册检查点、TOTP 及三种凭据导出。默认驱动为 `disabled`；测试驱动只有环境变量显式启用后才生成合成数据。没有改动原浏览器/协议授权、付费接码或推池写入引擎。

## 合并前修复

| 优先级 | 问题及使用影响 | 修复与验证 |
|---|---|---|
| P1 | `_click` 吞掉点击后的导航超时并尝试下一个选择器；同一次注册/验证码可能重复提交。 | 选定按钮点击失败后立即保留不确定状态，不换选择器或回车重发；断言只点击一次。 |
| P1 | 备用邮箱提交在检查点前发出；切换为 disabled 驱动还可能清空旧检查点，之后重试重新提交。 | 请求前记录意图；批次层统一检查副作用，不受驱动切换影响。 |
| P1 | TOTP 只有激活成功后才保存，响应丢失时可能已启用 2FA 却丢失密钥；后续 OAuth 又未传入该密钥。 | 激活前将密钥写入加密任务，明确区分待核对与已确认；OAuth 传入密钥。实际 Chromium 模拟激活响应丢失，验证导出、恢复与禁止重放。 |
| P1 | 注册入口和跳转可指向任意站点；建号响应只匹配 URL 路径，缺少来源与错误体校验。 | 限定官方 HTTPS 来源；只接受对应建号 POST 的明确成功，不把外部响应或 HTTP 200 错误体当作建号成功。会话邮箱缺失也不能进入绑定。 |
| P1 | 成功检查点在加密结果保存前删除；磁盘失败可能丢失恢复状态。 | 先保存账号结果，再清理检查点；写盘失败停止后续请求。失败注入验证检查点仍在。 |
| P1 | 同步响应事件中读取尚未完成的 body 可与跳转竞态，造成卡住或错误分类。 | 等待 `requestfinished` 后读取，先保留响应结果再在主流程更新状态；无法确认的响应仍停为待核对。 |
| P1 | 注册返回限流后仍处理后续邮箱；多个阶段各自重置超时。 | 限流停止批次，剩余项标记未处理；页面、邮件轮询、会话、TOTP 和 OAuth 共用剩余时间，网络等待设置上限。 |
| P2 | Graph 轮换 refresh token 未保存；读取忽略取消，旧邮件缺少时间/收件人校验。 | 先保存轮换凭据再读邮件；检查截止时间、取消、邮件日期与收件人。 |
| P2 | 适配器原始异常可能含密码/令牌并进入明文检查点；运行中新生成的密码不在日志脱敏列表。 | 检查点只记录固定错误，动态凭据加入脱敏列表。 |
| P2 | 资料页自动勾选所有复选框；注册设置显示未实现的步骤等待，浏览器窗口容易误认为支持网页接管。 | 不自动勾选条款；移除无效等待控件并明确窗口仅在服务器显示。恢复原推池页“待补手机转接码”入口的可见性。 |

## 保留的限制

- **真实平台端到端验收尚未完成。** 分支原有记录只证明一个邮箱建号接口成功，之后会话/OAuth 未完成且遇到手机验证。本轮不重新注册该邮箱，也不把模拟测试当作真实成功。
- **会话待恢复状态没有自动恢复按钮。** 已明确建号可以导出保存的账号密码，之后到授权页或手机接码页按需处理；不会在注册页重复建号。
- **注册页暂不支持网页浏览器接管。** 服务器本地窗口选项不等于远程画面；安全挑战和必选条款停止处理。
- **响应体被导航丢弃时采取保守结果。** 即便 HTTP 200，无法取得明确响应也可能标记待核对；不以重试建号解决，也不伪造成功。
- **没有购买短信、创建真实账号、写入真实后台或部署线上服务。** 本轮范围为源码合并、审查修复与模拟验证。

测试结果与环境记录见 `WEB_VALIDATION.md`。
