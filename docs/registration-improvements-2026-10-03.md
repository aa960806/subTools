# 注册功能对照优化

本轮仅扩展注册编排、注册结果界面和注册向现有功能的输入转交。普通授权、协议登录、短信订单、凭据刷新、转换和推池引擎未修改。

## 参考源码

- `myfanhua/turb-gpt-free-register`，`ffcda129bbabadcaaf73974bee44c64266f364ed`：`core/otp_utils.py` 的主题优先、HTML 清理、多语言识别；`core/registration_service.py:get_retry_info` 的按已完成阶段提供后续操作。
- `2951461586/GPT-Register-Tool`，`4fad5d4e862326096baedfe59c5e596437d42af0`：`browser_flow/page_state.py` 的登录密码页识别；`browser_flow/session.py` 的 Session 规范化、错误分类；`browser_flow/recovery.py` 的阶段预算；`registration_retry_guard.py` 的持久化邮箱保护。

根据上述行为独立实现，未引入整个参考工程或新增第三方运行依赖，也未在本地克隆参考仓库。

## 行为和边界

1. 登录密码页返回已有账号状态，禁止提交生成的注册密码。未知页面中的单个 numeric 输入不再作为 OTP 证据；已知验证路由仍支持数字验证码输入。
2. Graph 解析先读取主题，正文移除 HTML 样式和脚本；保留收件人、时间、基线排除与歧义检查。
3. Session 解析兼容顶层/嵌套结构，在明确建号后的 ChatGPT 页面可直接读取会话，不依赖固定 Cookie 名称。邮箱不匹配仍拒绝；429 立即停止，401/403 不继续轮询，临时异常只在读取预算内等待。
4. 注册邮箱记录使用现有 Store 加密、原子保存。任务和防重复记录都在提交前写入；写入失败停止操作。记录失败后，下一次注册从任务重建索引。成功记录和待核对记录不会因为新任务、归档或驱动变化消失。
5. 恢复入口只将已确认适用的账号准备到现有授权、接码或推池页面。未确认建号不能通过恢复按钮重新注册；TOTP 未确认时保留密钥，不自动再次激活。目标页面仍由用户主动开始，使用目标页的设置。
6. 页面等待使用阶段时间和总截止时间，OTP 等待不消耗提交后页面推进的等待预算。取消和未知提交结果继续保留检查点。

## 验证

执行结果见 `WEB_VALIDATION.md`。没有进行真实注册、付费接码或真实后台写入；模拟成功不代表外部平台当前成功率。
